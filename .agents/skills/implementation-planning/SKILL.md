# Implementation planning

## Required context and loading

Follow the host's authority and delivery rules; skill activation grants no permission.
Read the originating issue and prior discussion, approved intent and constraints,
host instructions, architecture and decisions, dependencies, toolchain information,
known workloads and relevant evidence.
Read [the planning method](references/method.md) before conducting the discussion.
It owns the detailed procedure; host rules own authorization and delivery policy.

## Discussion and handoff

Follow the method's discussion round, one meaningful decision question at a time.
Wait for the human and reflect the answer and trade-off before proceeding. Check
actual topic coverage before settling design; consequential unknowns remain open.
Keep recommendations, planning approval and completed implementation distinct.

## Output and optional resources

Keep the discussion record and bounded proposals in the host tracker, linked to
the origin, prior discussion and existing architecture or ADRs.
Load [issue formats](references/issue-formats.md) when drafting requested issues
or formalizing the discussion. Load [worked examples](references/examples.md)
only for a concrete record or exercise. Do not routinely load examples or reports.

## Unframed adapter

Follow [AGENTS.md](../../../AGENTS.md) for authority, document ownership and
library preferences. Follow [workflow guidance](../../../docs/workflow.md) and
[Engineering resources](../../../docs/decisions/README.md#engineering-resources)
for host conventions. The method governs issue
proposals and verified links; it does not execute the Go implementation skill.
